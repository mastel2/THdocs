# เช็กลิสต์เปิดบริการ THdocs แบบรัดกุม (ไม่ต้องมีทนาย)

แนวคิด: **เปิดให้น้อยที่สุดเท่าที่ยังใช้งานได้** เพื่อให้ความเสี่ยงทางกฎหมายและความปลอดภัยต่ำที่สุดโดยไม่ต้องเขียนสัญญาซับซ้อน
ขอบเขตที่ออกแบบไว้: ฟรี · ไม่มีบัญชีผู้ใช้ · ไม่เก็บเนื้อหาเอกสาร · ผู้ใช้ใส่ API key ของตนเอง (หรือใช้ AI ในเครื่อง)

> เอกสารนี้ไม่ใช่คำปรึกษากฎหมาย ถ้าจะเปลี่ยนขอบเขต (เก็บเงิน เก็บข้อมูลผู้ใช้ ออก key ให้ผู้ใช้ ขายให้องค์กร) ให้ปรึกษาทนายก่อน

## 0. ห้ามทำในช่วงเปิดตัว (เพื่อไม่ให้ความเสี่ยงเกินที่คุมได้)
- ❌ ห้ามตั้ง `THDOCS_SERVER_KEYS=1` หรือใส่ API key ของคุณบนเซิร์ฟเวอร์ที่เปิดสาธารณะ (ค่าใช้จ่ายบานปลาย + ภาระดูแลข้อมูลผู้ใช้)
- ❌ ห้ามตั้ง `THDOCS_ALLOW_CUSTOM_URL=1` (กันการใช้เซิร์ฟเวอร์ยิงไปเครือข่ายภายใน/SSRF)
- ❌ ห้ามเพิ่มระบบสมาชิก/ชำระเงิน/analytics/คุกกี้ — จะทำให้นโยบายความเป็นส่วนตัวที่เขียนไว้ไม่ตรงความจริง
- ❌ ห้ามเปิดบันทึกการเข้าถึง (access log) ของ reverse proxy เกินจำเป็น — ถ้าเปิด ให้แก้นโยบายความเป็นส่วนตัวให้ตรง

## 1. ก่อนเปลี่ยน repo เป็น public
- [ ] **ล้างประวัติ git:** ไฟล์ Word ทดสอบรุ่นเก่าในประวัติฝังชื่อผู้สร้าง `KEEP_DARK [-ART-]` — เจ้าของยืนยันแล้วว่า KEEP_DARK เป็นนามแฝงที่ใช้ในวงการไอทีและยอมให้เปิดเผยได้ จึงไม่จำเป็นต้องเขียนประวัติใหม่ (ฉบับล่าสุดของไฟล์ล้างชื่อแล้ว)
- [ ] ยืนยันว่ายอมให้เห็นอีเมล `art@keep-dark.com` ในประวัติ commit
- [ ] สแกนความลับอีกรอบ: `git grep -I -E "sk-ant-|sk-[A-Za-z0-9]{32}|AIza|ghp_|BEGIN (RSA |EC )?PRIVATE KEY"` และดู `git log -p` ว่าไม่มีไฟล์ที่ไม่ควรเปิด
- [ ] เปิดใน GitHub: Secret scanning + Push protection, Private vulnerability reporting, และตั้ง branch protection ให้ผ่าน PR + CI (ใช้ได้เต็มบน repo public)
- [ ] ตรวจ `LICENSE`, `NOTICE` ชื่อและอีเมลถูกต้อง · ไม่มีเบอร์โทรหรือข้อมูลส่วนตัวอื่น
- [ ] ตรวจว่าไม่มีไฟล์ตรา/ฟอนต์ในซอร์ส (`git ls-files | grep -iE "\.(ttf|otf)$"` ต้องว่าง)

## 2. เซิร์ฟเวอร์
- [ ] VPS ใหม่ที่ใช้เฉพาะงานนี้ · ล็อกอินด้วย SSH key เท่านั้น ปิดรหัสผ่าน · ไม่ใช้ root ตรง
- [ ] ไฟร์วอลล์เปิดเฉพาะพอร์ต 80/443 (และ SSH จาก IP ของคุณถ้าทำได้)
- [ ] เปิดอัปเดตความปลอดภัยอัตโนมัติของระบบปฏิบัติการ
- [ ] ติดตั้ง Docker แล้วรันตาม README: `docker compose --profile public up -d --build`
- [ ] ตั้งใน `.env`: `THDOCS_DOMAIN`, `THDOCS_PUBLIC_URL` (https), `THDOCS_SOURCE_URL` (ลิงก์ https ไปซอร์สโค้ดของ**เวอร์ชันที่รันอยู่** เช่น tag ใน GitHub — AGPL ข้อ 13), `THDOCS_RATE_LIMIT` (ค่าเริ่มต้น 60 ครั้ง/10 นาที/IP)
- [ ] DNS ชี้โดเมนมาที่เครื่องก่อนสั่งรัน (Caddy จะขอใบรับรองเอง)
- [ ] ไม่ต้องสำรองข้อมูลผู้ใช้เพราะไม่มี — สำรองเฉพาะ `.env` และ `deploy/Caddyfile`

## 3. หลังขึ้นระบบ ตรวจทุกครั้ง
- [ ] `node tools/ui-audit/ui-audit.mjs https://<โดเมน>` ผ่านครบ (ใช้ Edge ที่เชื่อใบรับรองจริง)
- [ ] `curl -sI https://<โดเมน>/` เห็น CSP, HSTS, X-Frame-Options, nosniff
- [ ] `/api/config` ไม่มี provider ที่ใช้ key ของเซิร์ฟเวอร์ และมี `sourceUrl`
- [ ] ลองใช้จริงบนมือถือ + เบราว์เซอร์อื่น (Chrome/Firefox/Safari — ยังไม่เคยทดสอบ)
- [ ] ลองโหมด AI ในเครื่อง (Ollama) จากหน้าเว็บ https: เบราว์เซอร์ต้องอนุญาตการเข้าถึงอุปกรณ์ในเครือข่ายภายใน ซึ่งยังไม่เคยทดสอบกับ Chrome จริง

## 4. ดูแลต่อเนื่อง
- [ ] ทุกเดือน: `npm audit`, ตรวจประกาศช่องโหว่ของ Next.js/React/ไลบรารีหลัก, อัปเดตเมื่อผ่านช่วงรอ แล้วรันเทสต์ + ui-audit ก่อนขึ้นระบบ
- [ ] ตรวจอีเมลแจ้งช่องโหว่ (`SECURITY.md`) และตอบภายใน 7 วัน
- [ ] ถ้าเกิดเหตุข้อมูลรั่ว: ปิดบริการ ตรวจสอบ แจ้งผู้ได้รับผลกระทบ/หน่วยงานกำกับตามกฎหมาย
- [ ] ถ้าผู้ใช้ร้องเรียนเรื่องข้อมูลส่วนบุคคล ตอบที่ art@keep-dark.com ตามนโยบาย

## 5. ต้องมีทนาย/ผู้เชี่ยวชาญก่อนทำสิ่งเหล่านี้

- รับโค้ดจากภายนอก (ต้องมี CLA ที่ตรวจแล้ว)

- ขายให้หน่วยงานรัฐ (ระเบียบจัดซื้อ ข้อกำหนดความมั่นคงปลอดภัย)
