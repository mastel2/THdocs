# THdocs

ร่างเอกสารราชการไทยด้วย AI แล้วจัดรูปแบบ .docx ตามแบบที่กำหนด

**หลักการ:** AI เขียนเฉพาะถ้อยคำ ส่วนรูปแบบ (ขอบ ฟอนต์ ระยะ เลขไทย ตำแหน่งลงนาม) และข้อมูลที่ต้องถูกต้อง (เลขที่ วันที่ ผู้ลงนาม คำขึ้นต้น/ลงท้าย) ระบบเติมเองแบบตายตัว
ข้อมูลใดไม่มี ระบบถามกลับก่อนร่าง หรือเว้นเป็นช่อง `[ระบุ: ...]` ที่ไฮไลต์ไว้ ไม่ให้ AI เดา

```
คำขอ ─► ดึงข้อเท็จจริง ─► ถามสิ่งที่ขาด ─► AI เขียนถ้อยคำ (JSON ตาม schema) ─► ประกอบเอกสาร ─► ตรวจตามระเบียบ ─► .docx
```

## ใช้งาน

ต้องมี Node.js 22+

```bash
npm install
cp thdocs.profile.example.json thdocs.profile.json   # ข้อมูลหน่วยงาน/ผู้ลงนาม
cp .env.example .env                                  # เลือก AI และใส่ key

npm run thdocs -- types
npm run thdocs -- draft "ขออนุมัติจัดอบรมพนักงาน 30 คน วันที่ 20 พ.ย. 2569" -t memo -o บันทึก.docx
npm run thdocs -- revise บันทึก.json "ทำให้ภาคเหตุกระชับขึ้น"
npm run thdocs -- render บันทึก.json      # แก้ไฟล์ร่าง .json เองแล้วสร้างใหม่ (ไม่เรียก AI)
npm run thdocs -- check บันทึก.json
```

### เว็บ

```bash
npm run web                                   # พัฒนา: http://localhost:3000 (เปิด Ollama/LM Studio ในเครื่องให้อัตโนมัติ)
npm run build -w @thdocs/web && npm run start -w @thdocs/web   # production
```

ขั้นตอนบนเว็บ: คำขอ → ตรวจ/เติมข้อมูลที่ขาด → AI ร่าง → พรีวิวทันที + ผลตรวจ + สั่งแก้/แก้เอง → ดาวน์โหลด .docx หรือพิมพ์เป็น PDF
ข้อมูลหน่วยงาน ตรา และร่างล่าสุดเก็บในเบราว์เซอร์ของผู้ใช้เท่านั้น เซิร์ฟเวอร์ไม่เก็บเนื้อหาเอกสาร

| ตัวแปรเซิร์ฟเวอร์ | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `THDOCS_SERVER_KEYS=1` | ปิด | ใช้ API key ของเซิร์ฟเวอร์แทนผู้ใช้ (เฉพาะติดตั้งใช้เองภายใน — เว็บสาธารณะผู้ใช้ต้องใส่ key เอง) |
| `THDOCS_OLLAMA_URL` / `THDOCS_LMSTUDIO_URL` | ปิดใน production | เปิดผู้ให้บริการในเครือข่ายของเซิร์ฟเวอร์ |
| `THDOCS_ALLOW_CUSTOM_URL=1` | ปิด | ให้ผู้ใช้ระบุ URL ของ AI เอง (เสี่ยง SSRF — เปิดเฉพาะภายใน) |
| `THDOCS_RATE_LIMIT` | 60 | จำนวนคำขอที่เรียก AI ต่อ IP ต่อ 10 นาที (นับในหน่วยความจำ — หลายเครื่องต้องย้ายไป Redis) |

### Word add-in

แผงข้างใน Word (เดสก์ท็อปและ Word Online) ใช้หน้า `/addin` ของเว็บเดียวกัน — ร่างแล้วแทรกลงเอกสารได้ 2 แบบ:
**แทนที่ทั้งเอกสาร** (WordApi 1.5 ขึ้นไป คัดลอกขอบกระดาษ หัว/ท้ายกระดาษ เลขหน้ามาครบ) หรือ **แทรกที่เคอร์เซอร์** (เฉพาะเนื้อหา)
และใช้ข้อความที่เลือกใน Word เป็นคำขอได้

- manifest: `https://<โดเมน>/addin/manifest.xml` (สร้างตามโดเมนจริง หรือกำหนด `THDOCS_PUBLIC_URL`)
- Office บังคับ **https** ทุก URL — ทดสอบในเครื่องต้องมีใบรับรองที่เครื่องเชื่อถือ (เช่น `next dev --experimental-https`)
- ติดตั้งทดสอบ: Word Online → แทรก → Add-ins → อัปโหลด add-in ของฉัน → เลือกไฟล์ manifest
  หรือ Word เดสก์ท็อปผ่าน Shared Folder Catalog (ศูนย์ความเชื่อถือ → แค็ตตาล็อก Add-in ที่เชื่อถือได้)

| ชนิด | |
| --- | --- |
| `external_letter` | หนังสือภายนอก (ข้อ ๑๑) |
| `memo` | บันทึกข้อความ แบบทั่วไป (ข้อ ๑๒) |
| `memo_proposal` | บันทึกเสนอเรื่อง (เรื่องเดิม / ข้อเท็จจริง / ข้อพิจารณา / ข้อเสนอ) |
| `stamp_letter` | หนังสือประทับตรา (ข้อ ๑๓–๑๔) — เว้นที่ประทับตราแดงและลงชื่อย่อ |
| `order` | คำสั่ง (ข้อ ๑๖) |
| `regulation` / `bylaw` | ระเบียบ (ข้อ ๑๗) / ข้อบังคับ (ข้อ ๑๘) — ระบบประกอบข้อ ๑ ชื่อ, ข้อ ๒ วันใช้บังคับ และข้อผู้รักษาการเอง |
| `announcement` | ประกาศ / แจ้งความ (ข้อ ๒๐) |
| `statement` / `news` | แถลงการณ์ (ข้อ ๒๑) / ข่าว (ข้อ ๒๒) — ไม่มีลายมือชื่อ |
| `certificate` | หนังสือรับรอง (ข้อ ๒๔) |
| `minutes` | รายงานการประชุม (ข้อ ๒๕) — ไม่ใช้ตราครุฑ |

ทุกชนิดมีตัวอย่างประจำ (`example` ใน `DocTypeDef`) ใช้ทั้งแสดงบนเว็บและเป็นข้อมูลทดสอบผังหน้า

## AI ที่รองรับ

| `--provider` | ข้อมูลออกนอกเครื่อง | ตั้งค่า |
| --- | --- | --- |
| `anthropic` (ค่าเริ่มต้น) | ใช่ | `ANTHROPIC_API_KEY` — ค่าเริ่มต้น `claude-opus-5-5` |
| `openai` | ใช่ | `OPENAI_API_KEY` + `--model` |
| `gemini` | ใช่ | `GEMINI_API_KEY` + `--model` |
| `ollama` | ไม่ | `--model` เช่น `qwen3.5:9b` |
| `lmstudio` | ไม่ | `--model` |
| `custom` | ตาม URL | `--base-url` + `--model` (เซิร์ฟเวอร์ OpenAI-compatible เช่น vLLM) |

ส่งให้ AI ภายนอก ระบบ**ปิดบังข้อมูลส่วนบุคคลก่อนส่ง**อัตโนมัติทุกขั้นตอน: ชื่อบุคคล (จับจากคำนำหน้า นาย/นาง/นางสาว/ดร./ผศ. ฯลฯ — ไม่จับตำแหน่งอย่าง นายกรัฐมนตรี นายอำเภอ),
เลขบัตรประชาชน โทรศัพท์ อีเมล เลขบัญชี ถูกแทนด้วยรหัส เช่น `⟦ชื่อ1⟧` แล้วใส่ค่าจริงกลับในผลลัพธ์ (`packages/core/src/privacy.ts`)
ถ้า AI ทำรหัสเพี้ยนจนคืนค่าไม่ได้ ตัวตรวจแจ้งเป็น error

เอกสารที่ระบุ `--secrecy` (ลับ/ลับมาก/ลับที่สุด) ส่งได้เฉพาะ AI ในเครื่องหรือเครือข่ายภายใน ทุกขั้นตอน (ดึงข้อมูล ร่าง แก้)
ชั้นความลับเก็บในไฟล์ร่าง การสั่งแก้จึงไม่ทำให้ชั้นความลับหาย

## โครงสร้าง

| ตำแหน่ง | หน้าที่ |
| --- | --- |
| `packages/core` | Document IR, ลำดับงาน (ถามข้อมูล → ร่าง → แก้), กฎตรวจกลาง, เครื่องมือภาษาไทย |
| `packages/templates-thgov` | ชุดแม่แบบหนังสือราชการ: schema ถ้อยคำ, การประกอบเอกสาร, กฎตรวจ, ผังหน้า (`layout.ts`) |
| `packages/render-docx` | IR → .docx (thaiDistribute, เลขไทย, ตราลอย, เลขหน้า, จุดตัดคำไทย) |
| `packages/render-html` | IR → HTML สำหรับพรีวิวและพิมพ์ PDF จากเบราว์เซอร์ |
| `apps/web` | เว็บ Next.js: หน้าใช้งาน + API (`/api/facts`, `/api/draft`, `/api/revise`, `/api/docx`, `/api/config`) |
| `packages/llm` | Claude (Anthropic SDK) + ผู้ให้บริการแบบ OpenAI-compatible |
| `apps/cli` | บรรทัดคำสั่ง |
| `tools/preview` | LibreOffice ใน Docker แปลง .docx → PDF/PNG เพื่อตรวจด้วยภาพ |

ชุดแม่แบบใหม่ (เช่น ISO) เพิ่มเป็น package ใหม่ที่ส่งออก `TemplatePack` โดยไม่ต้องแก้แกนหลัก
ผังหน้าเป็น IR กลาง ตัวแสดงผลปลายทางอื่น (Google Docs, Word add-in) แปลงจาก IR ชุดเดียวกัน

## ตรา ฟอนต์ และลิขสิทธิ์

- ระบบไม่มีตราครุฑหรือตราหน่วยงานให้ — ใส่ไฟล์ PNG ของหน่วยงานเองด้วย `--emblem` หรือ `emblemPng` ในโปรไฟล์ (ไม่มี = กรอบแทนตรา)
- เครื่องที่เปิดไฟล์ควรมีฟอนต์ TH SarabunPSK

## ข้อจำกัดที่ทราบ

- ค่าตำแหน่งบางค่าใน `layout.ts` เป็นค่าประมาณ (ระเบียบไม่ได้กำหนดเป็นตัวเลข) ตรวจด้วย Word แล้วแต่ยังไม่ได้เทียบซ้อนกับแบบฟอร์มทางการ
- ตารางคำขึ้นต้น/ลงท้ายครอบคลุมกรณีที่ใช้บ่อย กรณีพระบรมวงศานุวงศ์ระบบแจ้งให้ตรวจเอง
- การปิดบังชื่อบุคคลอาศัยคำนำหน้า — ชื่อที่ไม่มีคำนำหน้า หรือยศทหาร/ตำรวจที่ยังไม่อยู่ในรายการ จะไม่ถูกปิดบัง
- ยังไม่ทำ: บัญชีผู้ใช้, Word add-in, Google Docs, หนังสือชนิดอื่น, ชุด ISO
- โมเดลเล็ก (เช่น 9B) ร่างได้แต่คุณภาพไม่สม่ำเสมอ บางครั้งมีเศษข้อความแปลกปลอม — ระบบตรวจจับและแจ้งเป็น error ให้แก้ก่อนใช้
- พรีวิวบนเว็บไม่แบ่งหน้า ใช้ดูภาพรวม การแบ่งหน้าจริงดูจาก .docx
- ระบบสร้าง **ร่าง** — ผู้มีอำนาจต้องตรวจและลงนามก่อนใช้จริง
